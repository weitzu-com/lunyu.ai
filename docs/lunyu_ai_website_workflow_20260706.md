# lunyu.ai 网站全生命周期工作流

> 一句话定义：`lunyu.ai` 不是普通古籍展示站，而是一个「句子级经典内容库 + 200+ 语言理解系统 + 多语音频听读系统 + AI 受控问答入口 + SEO/GEO 分发系统 + 自动化运维闭环」。

项目使命：让世界任何角落的人，都能用自己的语言看懂《论语》，也能听懂《论语》；让《论语》在 AI 的加持下，服务幸福社会与幸福人类。

---

## 0. 第一性原理

### 0.1 网站到底是什么

网站不是页面集合，而是一个状态转换系统：

```text
用户困惑 / 搜索意图 / AI 问答入口
        ↓
可访问的母语内容结构
        ↓
可信的原文、解释、翻译、音频、对话
        ↓
用户获得理解、安顿、行动、教学、引用或再传播
```

所以 `lunyu.ai` 的建设不是“做一个网页”，而是持续维护四个函数：

```text
价值函数 V = 内容可信度 × 母语可理解度 × 听读可达性 × AI 交互满意度 × 信任
成本函数 C = 内容生产成本 + 翻译成本 + 音频成本 + API 成本 + 运维成本
风险函数 R = 内容失真 + 文化误读 + SEO 丢失 + API 泄露 + 部署漂移 + 版权风险
复利函数 F = 每次修复是否沉淀为数据、脚本、手册、测试、索引
```

生命周期管理目标：

```text
最大化 V 和 F
最小化 C 和 R
```

### 0.2 《论语》站点的本质约束

| 约束 | 推导出的原则 |
|---|---|
| 《论语》原文是稳定经典 | 原文层稳定、版本可追溯、不可被 AI 随意改写 |
| 最小理解单元是句子 | 所有数据、URL、音频、AI 上下文以句子为核心 |
| 200+ 语言会造成页面爆炸 | 必须数据驱动生成、分层发布、批量校验 |
| 经典概念难直译 | 术语库是一等资产，翻译必须保留文化边界 |
| 用户要“看懂”也要“听懂” | 音频、字幕、语速、无障碍是核心功能，不是附属功能 |
| AI 会放大错误 | AI 只能基于受控知识库回答，原文、解释、个人建议必须分层 |
| 搜索和 AI 搜索是主要入口 | URL、canonical、hreflang、sitemap、schema、llms.txt 是一等资产 |
| 运维可自动化但会误伤 | observe 先行，白名单自愈，canary 验证，关键扳机归人 |

### 0.3 北极星指标

**有效句子理解量 + 音频完成量 + AI 引用出现率 + 用户纠错闭环率**。

解释：

- 有效句子理解量：用户真的读到并停留，不只是页面被抓取。
- 音频完成量：证明“听懂论语”的使命在发生。
- AI 引用出现率：决定未来搜索与 AI 助手入口。
- 用户纠错闭环率：经典网站的信任来自持续纠偏。

## 2. 阶段 01：定位与边界

### 目标

把 `lunyu.ai` 定义清楚：给谁、解决什么、为什么值得长期做、哪些事坚决不做。

### 第一性判断

```text
用户真实需求 = 用自己的语言看懂论语 + 听懂论语 + 连接现实生活
产品承诺 = 把孔子及其弟子的经典对话，用 AI、多语言、音频送到每个想理解的人面前
不做事项 = 不做玄学噱头、不做低质自动内容农场、不把 AI 解释伪装成孔子原意
```

### 核心用户

- 全球读者：想读 Confucius / Analects，但被古汉语和语言障碍挡住。
- 中文学习者：需要原文、拼音、母语解释和听读。
- 教师与家长：需要可讲、可听、可引用的句子与主题。
- 组织管理者：关注君子、信、学、政、礼、仁等现实议题。
- 研究者：需要多版本、多语种、术语与版本对照。
- AI/SEO 生态：搜索引擎、AI 爬虫、问答引擎需要结构化可信内容。

### 红线

- 原文、现代解释、AI 建议必须分层展示。
- API Key 永不暴露到前端或公开仓库。
- 未审校内容不得标记为权威译文。
- 不伪造出处，不把现代观点塞回孔子原意。
- 对外发布前必须检查版权、敏感信息、凭证和源站真相。

### 产出物

- 项目使命一句话。
- 用户画像。
- 不做清单。
- 北极星指标表。
- 内容版权与底本策略。

### 门禁

- 能用 60 秒向外部人说明 `lunyu.ai` 是什么。
- 能列出三类核心用户和每类用户的第一需求。
- 能列出至少 5 个不做事项。

## 3. 阶段 02：内容底本与信息架构

### 目标

让《论语》的篇、章、句、主题、语言、音频、AI 上下文形成稳定骨架。

### 最小不可再分单元

网站的最小内容单元是“句子”，不是页面，也不是篇章。

每一句应包含：

- 原文。
- 篇章编号。
- 拼音或注音。
- 逐字词义。
- 现代中文解释。
- 英文枢纽译文。
- 目标语言译文。
- 文化背景说明。
- 生活化解释。
- 音频与字幕。
- AI 问答上下文。
- 质量状态与版本记录。

### 推荐 URL 结构

```text
/
/{lang}/
/{lang}/analects/
/{lang}/analects/{bookSlug}/
/{lang}/analects/{bookSlug}/{sentenceId}/
/{lang}/topics/
/{lang}/topics/{topicSlug}/
/{lang}/compare/
/{lang}/listen/
/{lang}/about/
/{lang}/method/
/api/chat
/api/random-sentence
/api/audio-manifest
/sitemap.xml
/robots.txt
/llms.txt
```

### 内容分层

| 层 | 内容 | 规则 |
|---|---|---|
| 原文层 | 《论语》原文、篇章、句读 | 稳定、可追溯、少改 |
| 注释层 | 字词、典故、背景 | 标明来源和解释边界 |
| 解释层 | 现代中文、儿童版、生活版 | 可优化，不伪称原意 |
| 翻译层 | 10 核心语种 + 200+ 长尾语种 | 标注版本、状态、生成批次 |
| 音频层 | 原文、解释、译文 TTS/真人音频 | 可听、可同步、可校验 |
| 主题层 | 仁、礼、义、信、孝、学、政、君子等 | 服务用户意图和内链 |
| 实体层 | Confucius、Analects、Chinese classics、sameAs | 服务信任与 GEO |
| 运营层 | Daily Sentence、Blog、Newsletter、课程资源 | 服务新鲜度和复访 |

### 关键决策

- URL 一经收录不可随意改变；必须改时使用 301，并同步 sitemap。
- 根路径 `/` 返回 200，不只做语言跳转。
- 语言版本 self-canonical，语言间用 hreflang 关联。
- x-default 全站一致，指向根路径或语言选择入口。
- 每个句子页是永久资产，主题页和听读页负责聚合。

### 门禁

- 核心 URL 模式稳定。
- 句子、篇章、主题、语言、音频之间有清晰内链。
- sitemap URL 数量与实际页面数量匹配。

## 4. 阶段 03：技术架构

### 目标

用简单、可部署、可回滚、可扩展的架构承载多语言经典内容和 AI 交互。

### 推荐架构

```text
用户
  ↓
Cloudflare DNS / CDN / WAF / Redirect
  ↓
Vercel / Cloudflare Pages 静态与边缘层
  ↓
Serverless / Edge Functions
  ↓
AI Model API + TTS API
  ↓
PostgreSQL / Object Storage / Vector Index
```

### 架构原则

| 问题 | 正解 |
|---|---|
| 原文和句子页稳定 | SSG/静态 HTML 优先 |
| AI 问答动态 | Serverless 代理，前端不直连模型 |
| 200+ 语言页面多 | 核心语言静态，长尾语言按需生成或分批构建 |
| 音频文件大 | 对象存储 + CDN，不进 Git 大仓 |
| 搜索与问答 | 结构化索引 + 向量检索，受控知识源 |
| 部署来源 | GitHub main 触发生产构建，避免长期直传漂移 |

### 数据建议

- 主数据：Git 中 JSON/MDX + PostgreSQL 双轨，早期可先 JSON。
- 搜索：Meilisearch、Typesense 或 PostgreSQL 全文索引。
- 向量：pgvector 或托管向量库。
- 音频：Cloudflare R2、S3、Vercel Blob 或同类对象存储。
- 分析：Plausible、Vercel Analytics、GA4 或 Cloudflare Web Analytics。

### 门禁

- `git HEAD`、GitHub `origin/main`、生产部署来源三者一致，或差异被明确记录。
- `.env`、API Key、TTS Key 不进入仓库。
- 生产域名、DNS、部署项目、数据库、对象存储有架构记录。

## 5. 阶段 04：句子级数据与多语言生产

### 目标

让 200+ 语言不是一次性奇观，而是可再生产、可校验、可维护的内容资产。

### 句子级 Schema

```json
{
  "id": "xue-er-001",
  "bookSlug": "xue-er",
  "bookTitleZh": "学而",
  "bookNumber": 1,
  "sentenceNumber": 1,
  "classicalChinese": "子曰：学而时习之，不亦说乎？",
  "pinyin": "zi yue: xue er shi xi zhi, bu yi yue hu?",
  "modernChinese": "孔子说：学习之后按时温习和实践，不也是令人愉快的吗？",
  "wordNotes": [
    {
      "word": "习",
      "meaning": "温习、实践、反复练习"
    }
  ],
  "themes": ["learning", "practice", "joy"],
  "translations": {
    "en": {
      "text": "The Master said: To learn and practice it at the right time, is this not a joy?",
      "status": "human_reviewed",
      "version": "v1",
      "updatedAt": "2026-07-06"
    }
  },
  "audio": {
    "zh-Hans": {
      "url": "/audio/zh-Hans/xue-er-001.mp3",
      "duration": 8.4,
      "status": "generated"
    }
  },
  "quality": {
    "sourceVerified": true,
    "humanReviewed": false,
    "expertReviewed": false,
    "riskNotes": []
  }
}
```

### 语言分级

| 等级 | 范围 | 策略 |
|---|---|---|
| A 级 | 英、西、阿、法、俄、葡、印地、日、韩、德、繁中 | 人工精修 + 专家抽检 |
| B 级 | 区域重要语种 | AI 翻译 + 自动检测 + 抽样人工审校 |
| C 级 | 长尾语种 | AI 翻译 + 完整性检测 + Beta 标识 |

### 翻译流水线

```text
语言清单
  ↓
句子级原文与现代中文
  ↓
英文枢纽译文
  ↓
批量多语种翻译
  ↓
JSON 修复与字段校验
  ↓
术语一致性检测
  ↓
文化误读检测
  ↓
页面生成或 API 供给
  ↓
抽检与全量完整性检测
  ↓
发布与反馈回流
```

### 术语库

必须建立跨语言术语库，避免核心概念漂移：

- 仁、礼、义、智、信、孝、忠、恕。
- 君子、小人、士、圣人。
- 学、习、思、知、行。
- 政、德、道、中庸。

每个术语包含：中文原词、现代中文解释、英文枢纽解释、可译/不可译边界、各语种推荐译法、禁用译法、典型句子。

### 数据质量门

| 检查项 | 标准 |
|---|---|
| 句子数 | 每语言句子数与底本一致 |
| 字段 | 原文、现代中文、译文、状态、版本完整 |
| 空值 | 不允许空字符串进入生产 |
| 术语 | 核心术语译法一致或有例外说明 |
| 乱码 | 抽查小语种、RTL、非拉丁脚本 |
| 版本 | 翻译日期、模型、批次可追溯 |

### 门禁

- 新增语言先小样试点，再批量生成。
- 连续 3 轮无新增完成时，剩余语言标注 Beta，不静默冒充完整。
- 所有数据生成脚本可复跑。

## 6. 阶段 05：音频与字幕生产

### 目标

把“听懂论语”做成核心能力，而不是文字站点的装饰。

### 音频类型

- 原文朗读。
- 现代中文解释朗读。
- 各语种译文朗读。
- 儿童友好版讲解。
- 慢速学习版。
- 连续听读播放列表。

### TTS 流水线

```text
文本定稿
  ↓
按语种选择 TTS 引擎与声音
  ↓
生成音频
  ↓
检测时长、静音、断句、音量、失败文件
  ↓
生成字幕时间轴
  ↓
人工抽检自然度
  ↓
上传对象存储
  ↓
生成 audio manifest
  ↓
页面和 API 引用
```

### 听读体验要求

- 逐句播放。
- 连续播放。
- A-B 循环。
- 语速调节。
- 原文与译文字幕同步高亮。
- 移动端锁屏播放尽量可用。
- 音频失败时有兜底，不影响文字阅读。

### 音频质量门

- 文件存在且 URL 返回 200。
- duration 合理，不为 0。
- 句子与字幕文本匹配。
- 采样抽听无明显读错、截断、长静音。
- RTL 与非拉丁语种字幕不破版。

## 7. 阶段 06：页面与交互建设

### 目标

把内容变成低认知负荷、高信任、高可读、高可听的体验。

### 核心页面

| 页面 | 目标 | 必备元素 |
|---|---|---|
| 首页 | 说明价值并导向阅读/听读/对话 | 语言入口、今日一句、播放、Ask Confucius、主题入口 |
| 篇章页 | 按篇阅读 | 篇名、句子列表、主题、播放全部、相关主题 |
| 句子页 | 深读一句 | 原文、拼音、注释、译文、音频、AI 解释、相关句子 |
| 听读页 | 连续听懂 | 播放队列、字幕、语速、语言切换 |
| 主题页 | 按现实问题进入 | 定义、相关句子、现代应用、Practice |
| 对照页 | 研究与教学 | 多语种、多版本并排 |
| About/Method | 建立信任 | 项目使命、AI 使用说明、审校流程、版权说明 |

### 首屏 MVP

用户进入网站后，第一屏应能完成：

1. 选择自己的语言。
2. 看到一句《论语》的原文、母语解释和播放按钮。
3. 向 AI 追问：“这句话对我的生活有什么启发？”

### 交互门禁

- 首页、句子、听读、语言切换、AI 问答五条核心路径手动通过。
- API 错误时页面有兜底，不出现 `undefined`。
- 移动端可读可点，音频控件不遮挡正文。
- RTL 语言 `dir="rtl"` 正确，不破版。
- 无障碍：键盘可操作、按钮有标签、音频有文字替代。

## 8. 阶段 07：AI 问答与安全边界

### 目标

让 AI 帮用户理解《论语》，但不让 AI 替代原文、伪造权威或放大误读。

### AI 可以做什么

- 用用户母语解释句子。
- 用生活场景举例。
- 对比不同译文。
- 根据年龄、职业、学习目的调整表达。
- 推荐学习路径。
- 回答限定在《论语》、孔子、儒家语境和已审核材料内的问题。

### AI 不能做什么

- 不伪造出处。
- 不把个人意见伪装成孔子原意。
- 不用现代鸡汤替代经典解释。
- 不绕开质量状态发布“权威译文”。
- 不对政治、宗教、民族议题做煽动性解释。

### RAG 知识库

AI 问答只使用受控知识源：

- 《论语》原文。
- 已审核现代中文解释。
- 已审核译文。
- 术语库。
- 主题索引。
- 经审核的背景材料。
- 版本与质量状态。

### 对话安全要求

- 输入长度封顶。
- 精确 Origin 白名单，不用模糊 `includes()`。
- 缺 Origin 不默认放行。
- IP 限流 + 上游模型预算。
- 前端校验响应关键字段。
- 日志脱敏，不记录用户敏感输入全文。

### 门禁

- AI 回复必须区分“原文”“解释”“一种可能的现代启发”。
- 引用句子必须能回链到站内句子页。
- 模型失败、限流、超时时前端有友好降级。

## 9. 阶段 08：SEO/GEO 基础设施

### 目标

让搜索引擎和 AI 系统理解、抓取、引用 `lunyu.ai`。

### SEO 必做

- title：匹配语言和搜索意图，长度可控。
- description：120-160 字符附近，强调句子、主题和听读价值。
- canonical：每页 self-canonical。
- hreflang：覆盖全部语言 + x-default。
- sitemap：可抓取、体积可控，必要时分片。
- robots.txt：声明 sitemap，放行正常爬虫。
- Open Graph / Twitter Cards：社交分享不空。
- 404：返回正确状态，不把错误页伪装成 200。

### GEO 必做

- `llms.txt`。
- Organization / WebSite / Book / Article / FAQPage / BreadcrumbList / AudioObject schema。
- sameAs：Wikipedia、Wikidata、GitHub、权威文本来源等。
- 每句答案胶囊：literal / meaning / practice。
- 概念页：Definition / Sentences / Modern / Practice。
- AI 爬虫可达性：GPTBot、ClaudeBot、PerplexityBot、Google-Extended、CCBot、Applebot、Bytespider。

### 关键教训迁移

- 根路径 302 可能造成 GSC 重定向错误；多语言站根路径应谨慎。
- sitemap 不要塞 200+ 语言 × 大量 URL × 全量 hreflang 到巨大响应体；页面 HTML 已有 hreflang 时，sitemap 可保持轻量。
- `cleanUrls + trailingSlash + rewrites` 叠加可能制造意外 301/404。
- Bing + IndexNow 是新站加速抓取的低成本动作。

### 门禁

- GSC / Bing 均提交 sitemap。
- 关键页面 Rich Results / Schema 校验无致命错误。
- `curl -I /sitemap.xml` 返回 200 且 Content-Type 正确。
- `site:`、GSC 覆盖率、AI 引用测试纳入周报。

## 10. 阶段 09：安全、版权与成本防线

### 目标

防泄露、防滥用、防误部署、防成本攻击、防版权误判。

### 安全清单

| 类别 | 检查 |
|---|---|
| 凭证 | API Key 不进仓库、不进前端、不进日志 |
| Origin | 精确 host 白名单 |
| 限流 | IP 限流 + 上游消费上限 |
| 安全头 | HSTS、CSP、X-Frame-Options、Referrer-Policy、Permissions-Policy、X-Content-Type-Options |
| 仓库 | push 前跑密钥扫描和敏感词扫描 |
| 依赖 | 定期 Dependabot / npm audit |
| 日志 | 用户输入脱敏，错误日志不暴露内部路径 |

### 版权与内容边界

- 原文底本、标点、注释来源必须记录。
- 公版内容与现代注释、译文、音频分别判断版权。
- AI 生成译文仍需保存生成批次和审校记录。
- 对外发布前，版权不确定内容默认不公开。

### 成本防线

- Serverless 调用量日监控。
- 模型 token 消耗日报或周报。
- TTS 生成成本按语种和批次记录。
- 异常请求触发告警。
- 模型失败时降级，不无限重试。

### 门禁

- 任一公开泄露 key 视为已泄露，必须轮换。
- 上线前 `rg` 扫描 key、token、secret、内部路径。
- `/api/chat` 压测确认限流生效。
- 版权状态不明的内容不得进入公开生产。

```text
先预览，后生产。
先观测，后切流。

```

### 发布 SOP

1. `git status` 确认工作树。
2. `git fetch` 确认本地与 `origin/main` 无危险分叉。
3. 检查部署项目和域名绑定。
4. 精确 `git add`，避免杂散文件混入。
5. 提交到分支，生成 Preview。

7. 合并 main，由 GitHub 触发生产构建。
8. 生产域名复测。

- 首页 5xx > 1% 且持续 5 分钟。
- `/api/chat` 5xx > 5% 且持续 5 分钟。
- 核心句子页大面积 404。
- 音频 manifest 大面积失效。
- 用户报告核心功能不可用且无法快速修复。

### 回滚动作

1. Vercel/Cloudflare 回滚到上一稳定部署或 DNS 指回旧源。
2. Purge Cache。
3. 验证首页、句子、音频、API。
4. 保留故障部署用于排查。
5. 48 小时内复盘。

## 15. 高风险坑位速查

| 坑 | 症状 | 根因 | 防线 |
|---|---|---|---|
| 多语言页面爆炸 | 构建慢、部署失败 | 200+ 语言全量静态一次生成 | 核心语言静态，长尾分批或按需 |
| 句子 ID 漂移 | 链接失效、引用错位 | 数据模型未固定 | 句子 ID 一经发布不可改 |
| 术语翻译漂移 | 仁、礼、君子等被乱译 | 无术语库 | 术语库 + 自动一致性检测 |
| AI 伪造权威 | 回答像孔子原意但无出处 | RAG 边界弱 | 原文/解释/建议分层 + 引用回链 |
| 音频大面积 404 | 播放失败 | manifest 与对象存储不同步 | 音频 URL 探测 + manifest 校验 |
| API 成本攻击 | 调用量异常 | Origin 校验弱、无限流 | 精确 Origin + IP 限流 + 上游预算 |
| GSC 重定向错误 | 大量 redirect error | 根路径只做 302 | 根路径返回 200 |
| sitemap 过大 | 无法抓取或 500 | 全量语言和 hreflang 塞入单文件 | sitemap 分片 + 轻量化 |
| RTL 破版 | 阿语等布局混乱 | 未设置 dir 或 CSS 不兼容 | RTL 样本测试 |
| 版权误发 | 不确定注释/译文公开 | 来源与权限未记录 | 内容版权状态字段 + 发布门禁 |
